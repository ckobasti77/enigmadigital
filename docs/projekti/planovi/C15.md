### 1.2 Kolone: tačni agregati i indeksi

Nov fajl **`convex/hubStore.ts`**:

export const pregledProjekta = projekatQuery({
  args: { od: v.string(), do: v.string(), sada: v.number() }, // beogradski ključevi; sada zaokružen na minut
  returns: pregledValidator,

Uloga je podrazumevana (`client_viewer`). Upit ne čita sat: `sada` šalje klijent, kao kod `kvotaGoogleAds` u C13. `od`/`do` moraju proći `jeDanKljuc`, uz `od ≤ do` i raspon ≤ 366 dana; inače `ConvexError("Neispravan period.")`.

### 3.3 Postojeći podaci (lenji prelazak, F10)

U `zamrzniDan`, kad korisnik nema nijedan lični red `napredakDan`:
1. **Podešavanja:** ako nema ličnog reda, kopira se stari red sa najvećim `updatedAt` među članstvima (`napredakPodesavanja.by_user_workspace`). Bez starih redova važi `PODRAZUMEVANO`.
2. **Potvrde:** unija starih redova po članstvima (`by_user_workspace_opseg`, opseg `trajno` i poslednjih 8 dana). `misija:*`, `bonus` i `dostignuce:*` se spajaju po ključu; za `nivo` se uzima najveća vrednost. Upisuju se kao lični redovi.
3. **Misije prošlih dana:** čitaju se stari `napredakDan` redovi svih članstava (`by_user_workspace_dan`, do 400 po projektu; ostatak kroz `scheduler`). Za svaki `dan` nastaje jedan lični red sa `misije` i `zamrznutoAt`, **bez `osnova`**. Kad više projekata ima red istog dana, misije se spajaju (najviše 3), a prednost ima red sa više ispunjenih misija.
4. **Zbir:** `osnova` se ponovo računa od najstarijeg događaja svih projekata (`najstarijiDogadjaj` po projektu, uzima se minimum), kroz postojeće `zakljuciDo`/`nastaviZakljucavanje` (14 dana po koraku). XP je izveden iz događaja, pa se ne gubi. Misije i potvrde su kopirane, pa se bonusi ne gube i stare proslave se ne ponavljaju.
5. Stari redovi se **ne brišu** (C19).

Za korisnika sa jednim projektom (danas Jovan u produkciji) lični zbir je jednak starom zbiru tog projekta; test to tvrdi (§8).

### 5.1 Tabela

`pulsGreskaValidator` = `"istek" | "mreza" | "http" | "preusmerenje" | "nije_json" | "prevelik" | "los_format" | "adresa_van_sajta"`. U `purgeMap.ts`: `EXTRA_TABLE_OWNERSHIP.pulsSnimci = { excluded: "Brojke sa sopstvenog sajta projekta, ne podaci provajdera; čisti ih Puls posle 90 dana." }`.

- `convex/crons.ts`: `crons.interval("puls", { minutes: 15 }, internal.puls.pokupiSve, {});`. Puls nije Meta posao, pa ide na `interval`, po pravilu iz komentara fajla.

### 5.3 Validacija odgovora (format iz PLAN §11)

Čista funkcija u **`convex/lib/puls.ts`**: `parsirajPuls(tekst: string, sada: number): { ok: true, vreme, metrike, oznake } | { ok: false, kod, poruka }`.

| Pravilo | Greška |
|---|---|
| telo je JSON objekat | `nije_json` |
| `vreme` je ISO 8601 string, `Date.parse` uspeva, a vreme nije više od 5 min u budućnosti | `los_format` |
| `metrike` je objekat sa 1–20 ključeva; ključ odgovara `^[a-z0-9_]{1,40}$`; vrednost je konačan broj, `|x| ≤ 1e12` | `los_format` („Puls je vratio 23 metrike; najviše je 20.“) |
| `oznake` (opciono) je objekat; svaki ključ postoji u `metrike`; vrednost je string od 1–60 znakova, bez kontrolnih znakova | `los_format` |
| ostali ključevi najvišeg nivoa | ignorišu se |
| veličina > 64 KB | `prevelik` (pre parsiranja) |

## 6. Leadovi sa sajta (C17)

### 6.1 Ruta

U `convex/http.ts`: `http.route({ path: "/projekti/lead", method: "POST", handler })` i `http.route({ path: "/projekti/lead", method: "OPTIONS", handler })`. Logika je u novom **`convex/leadSajt.ts`** (pomoćnik za `httpAction` i `internalMutation primiLeadSaSajta`), da `http.ts` ostane samo spisak ruta.

Redosled u `POST`:
1. `Content-Type` mora sadržati `application/json`, inače 415; `Content-Length` (ili pročitan tekst) mora biti ≤ 16.384, inače 413.
2. Bearer token, po istom obrascu kao `http.ts:1887-1904`: `sha256Hex` → `internal.ingestTokensStore.findValidTokenByHash` → 401 `{ greska: "neispravan token" }`. C17 izdvaja proveru u `tokenIzZaglavlja(request)` i `nadjiToken(ctx, token)` u `convex/lib/ingestToken.ts` i koristi ih u novoj ruti; postojeće rute se ne prepisuju.
3. Namena: `token.namena !== "sajt"` → 403 `{ greska: "token nije za formu na sajtu" }`.
4. Origin (F16): ako postoji zaglavlje `Origin`, njegov host (mala slova, bez `www.`, bez porta) mora biti u `podesavanjaProjekta(ws).sajtovi.vrednost` (čita se kroz interni upit). Inače 403 `{ greska: "nedozvoljen izvor" }`, bez upisa.
5. Kapa (§6.3) → 429 `{ greska: "previše zahteva" }` i `Retry-After`.
6. `JSON.parse` i zod šema `leadSajtSchema` (nov `convex/lib/leadSajt.ts`; zod je već zavisnost) → 422 `{ greska: "neispravno telo", polja: [...] }`, kroz isti `greskeValidacije` kao kod uvoza.
7. `primiLeadSaSajta` (§6.5–6.6) → 200 `{ ok: true, id, duplikat }`.
8. `markTokenUsed`.

Sva tela odgovora idu kroz postojeći `ingestOdgovor` (`Cache-Control: no-store`), uz CORS zaglavlja kad je origin dozvoljen.

**Telo** (PLAN §11 + F21):

| Polje | Pravilo |
|---|---|
| `ime?` | string, 1–120 znakova |
| `email?` | email ≤ 254 (zod `email()`); čuva se `trim().toLowerCase()` |
| `telefon?` | string ≤ 40; za uparivanje `normalizePhoneRs` (ako ne uspe, čuva se sirov, bez uparivanja) |
| `firma?` | string, 1–160 znakova |
| `poruka?` | string ≤ 2.000 |
| `stranica?` | `https://` URL ≤ 500; čuva se samo kad je host u `sajtovi`, inače `null` (lead se ne odbija) |
| `utm?` | objekat sa `source/medium/campaign/term/content`, svaki ≤ 100 |
| `eventId?` | `^[A-Za-z0-9_-]{8,64}$` |
| `klijent?` | `{ ip?: IPv4/IPv6 ≤ 45, userAgent?: ≤ 400, fbp?: ≤ 120, fbc?: ≤ 200 }` |
| `saglasnost?` | `{ marketing: boolean }` |
| uslov | bar jedno od `email` i `telefon`, inače 422 „Treba email ili telefon.“ |
| nepoznata polja | odbijaju se (`strict()`), da greška u ScanMe-u ne prođe tiho |

### 6.2 Token i namena

### 6.3 Ograničenje učestalosti

Ide preko postojećeg `internal.publicRouteLimit.claimRouteCall` (fiksni prozor od 1 h):
- po tokenu: ruta `projekti-lead:<tokenId>`, kapa `PROJEKTI_LEAD_PO_TOKENU_HOURLY_CAP = 60`;

### 6.4 CORS po `sajtovi`
