# S01 — Arhitektura spajanja: tehnički plan za S02–S06 i okvir za web

Ovo je plan za prenos Devotion backenda u Enigmu. Sproveđuju ga koraci S02–S06, a S07 ga koristi za web. Svi brojevi u planu su provereni nad snimkom (`main @ c05c40f`) i nad Enigmom (grana `spajanje-run`). Pri sastavljanju plana nijedan fajl u repou nije menjan.

**Kako je merenje urađeno**
- Brojevi za Devotion potiču iz `rg --no-ignore` nad `packages/backend/convex`, `packages/shared/src` i `apps/web`.
- Brojevi za Enigmu potiču iz dve provere koje samo čitaju:
  - `verify-purge-coverage`: danas ima 145 aplikacionih tabela i 7 auth tabela.
  - `verify-pristup`: danas ima 379 javnih funkcija, 364 omotačem i 15 sa `// javno:`, plus 32 direktna poziva na frontu.

**Oznake koje se koriste kroz ceo plan**
- **P** je projektna funkcija. Pravi se kroz `projekatQuery/Mutation/Action` sa `uloga: "urednik"`.
- **P!** je isto, ali sa `uloga: "owner"`.
- **L** je lična funkcija (`prijavljenQuery/Mutation`).
- **I** je interna funkcija.

export async function requireClanProjekta(ctx: ReadCtx, workspaceId: Id<"workspaces">): Promise<Actor> {
  let projekat: Projekat;
  if (ctx.projekat !== undefined) {
    // Omotač je već proverio članstvo i ulogu. Dokument iz argumenta mora biti iz TOG projekta.
    if (ctx.projekat.workspaceId !== workspaceId) throw new ConvexError(PORUKE_PROSTORA.tudjiProjekat);
    projekat = ctx.projekat;
  } else {
    // Lični nivo (prijavljen*): članstvo u projektu dokumenta, bar urednik.
    projekat = await requireProjekat(ctx, workspaceId, "urednik");
  }
  const workspace = await ctx.db.get(workspaceId);
  if (workspace === null || workspace.arhiviran === true) throw new ConvexError(PORUKE_PROSTORA.projekatNijeDostupan);
  const clan = await ctx.db.query("members")
    .withIndex("by_user_workspace", (q) => q.eq("userId", projekat.userId).eq("workspaceId", workspaceId))
    .first(); // nikad .unique() (D20)
  if (clan === null || clan.role === "client_viewer") throw new ConvexError(PORUKE.urednik);
  const profile = await requireProfile(ctx);
  const isManager = clan.role === "owner" || (await jeVlasnikPlatforme(ctx, projekat.userId));
  return { profile, workspace, membership: clan as Clanstvo, isManager };
}

### 3.7 Kako se odbija `client_viewer` (O5)

1. Svaka P funkcija nosi eksplicitno `uloga: "urednik"` ili `"owner"`, **i to važi i za upite**, jer omotač inače podrazumeva `client_viewer`. Odgovor je `forbidden` sa porukom „Ovu radnju može da izvede urednik ili vlasnik projekta.“
2. Adapter van omotača radi `requireProjekat(ctx, wsId, "urednik")`. U omotaču je provera `clan.role === "client_viewer"` odbrana u dubinu.
3. Spiskovi ga preskaču: `listMyActiveWorkspaces`, `aktivniClanoviProjekta`, `ljudiSaKojimaDelim`, `prostor.projekat.listForCurrent` i `listMembers`.
4. `createNotification` ne šalje obaveštenje primaocu bez `clanstvoProfila`.
5. `obezbediProfil` ne pravi profil korisniku koji je samo `client_viewer` (D16).
6. **Čuvar** `scripts/verify-prostor-pristup.ts` (S02, `npm run verify:prostor-pristup`, pravila u `lib/prostor-pristup-cuvar.ts`, test pored) pada ako u `convex/prostor/**` važi bilo šta od sledećeg:
   - `projekat*({…})` nema svojstvo `uloga` vrednosti `"urednik"` ili `"owner"`;
   - postoji `// javno:`;
   - posle `.query("members")` stoji `.unique()`;
   - čita se `.role === "admin"` ili `.role !== "admin"`;
   - pominju se tabele `"startups"`, `"startupMembers"` ili `"appState"`.

   Test S02 obuhvata sledeće:
   - owner i urednik prolaze;
   - client_viewer, stranac, arhiviran projekat i dokument iz drugog projekta ne prolaze;
   - provera vlasnika platforme radi.

## 9. Rizici i provera

1. **Ograničenja čitanja i OCC**
   - Transakcija ima granicu od 32.000 dokumenata i 4.096 opsega indeksa (`convex/projekti.ts:157`), a mutacija najviše 1.000 zakazanih funkcija.
   - Opseg od 50 projekata ne sme da poveća budžet čitanja. U `inbox.pending` sa 50 projekata × 31 ideja × 2 opsega to bi bilo oko 3.100 opsega. Zato važi globalni plafon od 20 × 31 ideja, a preko njega `capped: true` (S06).
   - `chat.listConversations` i `unreadSummary` već imaju globalne plafone (400, 300, 500). `expoPushTokens.computeBadge` (do 50 × 100 dokumenata) je neaktivan bez tokena.
   - S04 i S06 testiraju scenario sa 51 projektom.
   - OCC: adapter dodaje u skup čitanja `workspaces` dokument i `members` redove. Enigma ih menja retko (podešavanja), pa je rizik od sukoba nizak. Vruća mesta ostaju kao u Devotionu: `chatChannels.lastMessageAt`, `chatReads.unreadCount` i `pages.revision`. Convex tada sam ponavlja mutaciju.
2. **Opseg crona `remindDueTasks`:** Devotion je imao jednu transakciju, 100 startupa × 200 zadataka, odsecanje bez signala i pad cele transakcije pri prekoračenju. Zamena je fan-out iz §3.6e (50 projekata po strani, 100 zadataka po transakciji, nastavak kroz kursor, isti `now` kroz nastavke, dedupe ključ ostaje). Test proverava da 150 zadataka dobija podsetnik i da niko nije odsečen.
3. **Tiho vreme i Beograd**

     - `Intl` sa `Europe/Belgrade` u `lib/notifications.ts:50-98`;
