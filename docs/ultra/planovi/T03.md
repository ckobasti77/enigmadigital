### 1.2 Tip i čista funkcija
Nov fajl **`convex/lib/statusVeze.ts`** (čist: ne čita bazu ni sat). Gradi se na `razlogZdravlja` iz `zdravljeVeza.ts`, pa hub, birač i ostatak aplikacije po konstrukciji daju isti odgovor.

```ts
export type VrednostStatusa = "radi" | "trazi_paznju" | "nije_povezano";
export type RazlogStatusa =
  | "server_nije_podesen" | "token_istekao" | "greska_veze" | "pao_prolaz"
  | "token_istice" | "zastao" | "stari_podaci"   // → trazi_paznju
  | "brisanje_u_toku";                            // → nije_povezano
export type UlazStatusa = VezaZaZdravlje & {
  provider: Provider;
  /** max(metaSyncJobs.lastDataAt) za provajdera — kad je podatak stvarno upisan. */
  poslednjiPodatak?: number;
  /** null = provajder nema serversku konfiguraciju koju proveravamo. */
  serverPodesen: boolean | null;
  /** Kraj poslednjeg USPEŠNOG prolaza (iz paketa od 40 prolaza, kao zvono danas). */
  poslednjiUspeh: number | null;
};
export type StatusVeze = {
  provider: Provider;
  vrednost: VrednostStatusa;
  razlog: RazlogStatusa | null;
  za?: number;                 // dani do isteka ili sati bez podataka
  podaciOd: number | null;     // max(lastSyncAt, ok prolaz.finishedAt, poslednjiPodatak)
  istice: number | null;       // expiresAt
  poslednjiUspeh: number | null;
};
export function statusVeze(provider: Provider, ulaz: UlazStatusa | null, sada: number): StatusVeze;
export function porukaStatusa(s: StatusVeze, sada: number): { recenica: string; radnja: { oznaka: string; href: string } | null };
export function zbirStatusa(s: readonly StatusVeze[]): { radi: number; traziPaznju: number; nijePovezano: number; prvaPaznja: Provider | null; prvaNepovezana: Provider | null };
export const PROVAJDERI_STATUSA: readonly Provider[]; // ga4, openreply, meta_ig, meta_fb, threads, meta_ads, google_ads, youtube (+ google_business samo ako ima vezu)
```

**Pragovi (P3, sa brojevima):**
- **Token:** `TOKEN_ISTICE_MS` u `zdravljeVeza.ts` i `TOKEN_EXPIRY_WARNING_MS` u `lib/token-expiry.ts` idu sa **14 na 7 dana**. `lib/zdravlje-veza.test.ts` već proverava da su jednaki. `TOKEN_KRITICNO_MS = 2 dana` ostaje (za hub je to crvena; u statusu je i dalje „traži pažnju", a zvono daje visoku hitnost).
- **Podaci:** „traži pažnju" kad `sada − podaciOd > pragoviStarosti(provider).zuto`, tj. `max(24 h, 2 × razmak redovnog prolaza)`. To je 24 h za sve provajdere osim Threads-a, koji ima 48 h jer mu je redovan prolaz jednom dnevno (`OCEKIVANI_RAZMAK_H`). Provajder bez redovnog prolaza (`google_business`) nema pravilo starosti.
- **Zastoj:** prolaz koji teče duže od 15 min (`ZAGLAVLJEN_MS`).
- **Natpis „podaci od …"** uz fokus broj i u traci: kad je `sada − podaciOd > 24 h`, ravno za sve (§5.1).

**Redosled odluke (prvo pravilo koje važi pobeđuje):**
1. nema reda veze → `nije_povezano`, razlog `null`;
2. `status === "disconnecting"` → `nije_povezano`, razlog `brisanje_u_toku`;
3. `serverPodesen === false` → `server_nije_podesen`;
4. pa redom kao u `razlogZdravlja`: `token_istekao` (status `expired` ili `expiresAt ≤ sada`), `greska_veze`, `pao_prolaz` (pao, a posle njega ništa svežije), `token_istice` (≤ 7 d), `zastao`, `stari_podaci`;
5. inače `radi`.

`razlogZdravlja` dobija jedan opcioni ulaz, `poslednjiPodatak`, koji ulazi u `max` za starost. Hub ga ne šalje i ponaša se kao do sada.

**Radnja po razlogu.** `href` je uvek `/settings?tab=integracije#veza-<provider>`; T04 dodaje `id="veza-<provider>"` na karticu svake veze.

| Razlog | Oznaka radnje |
|---|---|
| `token_istekao`, `token_istice` | „Poveži ponovo" |
| `greska_veze`, `pao_prolaz`, `zastao`, `stari_podaci` | „Sinhronizuj" |
| `server_nije_podesen` | „Otvori uputstvo" |
| `nije_povezano` | „Poveži" (samo u Podešavanjima i praznom stanju kanala, nikad u tački) |
| `brisanje_u_toku`, `radi` | bez radnje |

**Tekstovi poruka.** Naziv dolazi iz `INTEGRACIJA_NAZIV` (`convex/lib/notifications.ts:81`), a trajanje iz postojeće `trajanje()` (`notifications.ts:237`, već izvezena):

### 6.3 Proba pre uključivanja
- **Upit `probaPravila`** (`projekatQuery`, args `{ scope, condition }`) radi i pre čuvanja, i za postojeće pravilo. Čita samo bazu (`adInsights`, `adCampaigns`, `adSets`, `ads`, `ruleFirings` za pauzu); upit ne može da zove mrežu. Vraća:
  ```ts
  { valuta: string | null, pisanjeUkljuceno: boolean /* process.env.ADS_WRITE_ENABLED === "true" */,
    pogodjeni: { naziv, targetId, vrednost, prag, uPauzi: boolean }[],
    najblizi: { naziv, vrednost, procenatPraga } | null,
    ispodMinPrikaza: number, prozorDana: number }
  ```
- **Server sprečava uključivanje bez probe.**
  - `toggleRule` dobija `probaPotvrdjena: v.optional(v.boolean())`. Za pravilo sa `pause` ili `pause_and_notify` i `enabled: true` bez `probaPotvrdjena === true` baca `ConvexError("Pre uključivanja pogledaj probu.")`.
  - Isto važi za `createRule` i `updateRule` kad je `enabled: true`.
  - Pravila koja samo javljaju se uključuju bez probe.
- **UI:** nov `components/app/rules/rule-proba-dialog.tsx`, koji se otvara na Switch kartice i na Switch urednika pri uključivanju pravila koje pauzira.
  - **Naslov:** „Proba pre uključivanja".
  - **Telo:**
    - „Sada bi pauziralo: {N} {kampanju/kampanje/kampanja}", pa spisak redova „{naziv} · {Cena po rezultatu} {643,00 EUR} > prag {1.300,00 EUR}" (kampanje u pauzi nose „već okinuto, čeka {h} h");
    - za N = 0: „Sada ne bi pauziralo nijednu kampanju.";
    - kad `!pisanjeUkljuceno`: „Pauziranje je sada isključeno na serveru; pravilo bi samo poslalo mejl.";
    - u dnu: „Proba čita podatke iz baze za poslednja {N} dana i ništa ne menja na Meti."
  - **Dugmad:** „Uključi pravilo" (`primary`) šalje `toggleRule({ …, enabled: true, probaPotvrdjena: true })`; „Odustani" je `ghost`.

### 6.4 Kartica: vrednost prema pragu
`rules-list.tsx` po kartici čita `probaPravila` sa uslovom pravila (Convex deduplikuje pretplatu) i ispod rečenice piše:
